================================================================================
COROnet - FRONTEND FULL DOCTOR DISCUSSION GUIDE
================================================================================

Purpose:
This file is a full study reference for discussing the frontend with a doctor or
supervisor. Every bullet includes HOW IT WAS CREATED: which React/TypeScript
pieces and npm libraries were used in this project (see package.json).

Legend — “HOW CREATED” shorthand:
- React: functional components (.tsx), JSX, hooks (useState, useEffect, useMemo,
  useCallback, useContext, etc.)
- react-router-dom: BrowserRouter, Routes, Route, Link, NavLink, Navigate,
  Outlet, useNavigate, useLocation, useParams, useSearchParams
- Vite: dev server, build; import.meta.env.VITE_* for environment variables
- TypeScript: types for props, API shapes, safer refactors
- CSS: paired .tsx + .css files; global styles in src/index.css
- Context API: createContext + Provider + custom hooks (e.g. useAuth)
- fetch: browser Fetch API (no axios in dependencies)


--------------------------------------------------------------------------------
1) FRONTEND OVERVIEW (WHAT IT IS RESPONSIBLE FOR)
--------------------------------------------------------------------------------

The frontend is a React + TypeScript + Vite single-page application (SPA).
HOW CREATED: Vite scaffolds the app; react + react-dom render UI; entry in
src/main.tsx uses createRoot(...).render(<StrictMode><App/></StrictMode>).

It is responsible for:
- User interface (forms, pages, navigation, dashboard, uploads, reports)
  HOW CREATED: page components under src/pages and src/pages/app; layout under
  src/components/layout; icons via lucide-react; motion via framer-motion.
- Session experience (login/register state in browser)
  HOW CREATED: AuthContext (React Context + hooks); token in localStorage;
  API calls with fetch to /api/auth/*.
- Calling backend APIs (auth + scan operations)
  HOW CREATED: fetch + JSON or FormData; base URL import.meta.env.VITE_API_URL
  || http://localhost:4000; Authorization header from src/lib/apiAuth.ts.
- Showing status, loading, errors, offline states, and confirmations
  HOW CREATED: ToastContext + ConfirmContext (with framer-motion for overlays);
  OfflineBanner; LoadingBar; ErrorBoundary class component pattern.
- Displaying and organizing medical workflow screens for users
  HOW CREATED: React Router nested routes; AppLayout shell with Sidebar/Header.

It is NOT responsible for:
- Database operations / password hashing / JWT issuing / file storage / server
  authorization enforcement — those belong to the backend; the frontend only
  consumes HTTP APIs.

  HOW CREATED: React 19 entry; createRoot on #root; imports ./index.css.

  HOW CREATED: React Context API files: AuthContext, ThemeContext, ToastContext,

- src/hooks/
  HOW CREATED: custom hooks — usePageTitle (useLocation + route map), useFocusTrap
  (DOM focus management for accessibility).

- src/lib/

4) ROUTING SYSTEM (PUBLIC VS PROTECTED + HOW CREATED)
--------------------------------------------------------------------------------

HOW CREATED (overall): react-router-dom in src/App.tsx — BrowserRouter, nested
Route elements, ProtectedLayout for /app, AppLayout as inner layout with Outlet.

Public routes (examples):
- /, /login, /signup, /forgot-password, /onboarding, /privacy, /terms
  HOW CREATED: top-level <Route path="..." element={<Page/>} /> declarations.

Protected section:
- /app/* under ProtectedLayout; inner routes under AppLayout
  HOW CREATED: parent Route element={<ProtectedLayout/>} with child routes;
  AppLayout uses <Outlet/> for nested page content; useAuth for guard logic.

Protected child routes (examples):
- /app, /app/patients, /app/patients/:id, /app/upload, /app/analysis,
  /app/reports, /app/reports/:id, /app/compare, /app/share, /app/analytics,
  /app/admin, /app/settings, /app/notifications, /app/help, /app/search, /app/status
  HOW CREATED: Route path strings + page components; dynamic segments :id read
  via useParams in page components.

Fallback:
- * -> NotFound
  HOW CREATED: catch-all Route path="*".


--------------------------------------------------------------------------------
5) AUTHENTICATION ON FRONTEND (REAL FLOW + HOW CREATED)
--------------------------------------------------------------------------------

Primary implementation:
- src/contexts/AuthContext.tsx
  HOW CREATED: createContext; AuthProvider with useState for user/token/loading;
  useCallback for login/register/loadUser; useEffect to restore session;
  fetch for POST /api/auth/login, POST /api/auth/register, GET /api/auth/me.

Token storage:
- localStorage key AUTH_TOKEN_KEY = 'coronet-token' (see src/lib/apiAuth.ts)
  HOW CREATED: synchronous browser API; read in authHeaders() for fetch calls.

Route guarding:
- ProtectedLayout + useAuth()
  HOW CREATED: react-router-dom Navigate to /login when !user; Outlet when ok.

Security note (discussion):
- Token in localStorage is convenient for demos; XSS is the main concern.
  HOW CREATED: no httpOnly cookies in this stack — purely client-stored JWT string.

6) GLOBAL CONTEXTS (WHAT EACH ONE DOES + HOW CREATED)
--------------------------------------------------------------------------------

- AuthContext — session, login, register, logout
  HOW CREATED: React Context + fetch + localStorage (above).

- ThemeContext — light/dark (or theme toggle)
  HOW CREATED: Context + state; typically toggles data-theme / CSS variables
  (paired with global CSS).

- ToastContext — global notifications
  HOW CREATED: Context holds toast list; framer-motion AnimatePresence for
  enter/exit; components call addToast.

- ConfirmContext — “Are you sure?” modal
  HOW CREATED: Context exposes confirm(); modal UI uses framer-motion for overlay
  animation.

Doctor point: Context avoids prop drilling; for larger apps you might add Zustand
/ Redux — not in package.json here.

8) API COMMUNICATION FROM FRONTEND (+ HOW CREATED)
--------------------------------------------------------------------------------

- Base URL: import.meta.env.VITE_API_URL || 'http://localhost:4000'
  HOW CREATED: Vite exposes only VITE_* env vars to the client bundle.

- JSON requests (auth)
  HOW CREATED: fetch(..., { method, headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify(...) }).

- Multipart upload (DICOM)
  HOW CREATED: FormData + formData.append('file', file); fetch POST without
  forcing Content-Type (browser sets boundary).

- Binary download (DICOM file bytes)
  HOW CREATED: fetch(...); res.arrayBuffer() where needed for parsing/viewing.

- Auth header helper
  HOW CREATED: src/lib/apiAuth.ts — authHeaders() adds Authorization: Bearer.

- Errors / offline
  HOW CREATED: try/catch around fetch; res.ok checks; user messaging via toasts
  or inline text; OfflineBanner listens to browser online/offline.

15) COMMON DOCTOR QUESTIONS (+ HOW CREATED ANSWERS)
--------------------------------------------------------------------------------

Q: Why React + Vite?
A: Component model + TypeScript + fast developer experience; Vite builds a
   modern ES module dev server and optimized production bundle.

Q: How is routing done?
A: react-router-dom nested routes; protected /app tree; layouts with Outlet.

Q: How is global state handled?
A: React Context for auth/theme/toasts/confirm — no Redux in package.json.

Q: How do you animate the UI?
A: framer-motion on pages and overlays; lucide-react for icons.

Q: How is DICOM handled in the browser?
A: dicom-parser for metadata/bytes; react-zoom-pan-pinch for zoom/pan in
   Analysis Studio; full validation still on server.


--------------------------------------------------------------------------------
16) ONE-MINUTE SUMMARY (FOR OPENING REMARKS)
--------------------------------------------------------------------------------

The COROnet frontend is a React 19 + TypeScript SPA built with Vite, routed with
React Router, styled with component-scoped CSS, and enhanced with Framer Motion
and Lucide icons. It uses React Context for session and UI systems, the Fetch API
for REST integration, dicom-parser and react-zoom-pan-pinch for imaging workflows,
and html2canvas + jsPDF where PDF export is implemented. The structure separates
public marketing/auth pages from a protected /app dashboard with a shared layout.
