Purpose:
End-to-end pipeline from browser to database and disk, for doctor discussion.
Every subsection includes HOW CREATED: concrete tools, libraries, and patterns.

Legend — “HOW CREATED”:

--------------------------------------------------------------------------------
1) SYSTEM-LEVEL ARCHITECTURE
--------------------------------------------------------------------------------

Three layers:

1) Frontend (SPA)
- Role: UI, routing, client state, HTTP client to API.
- HOW CREATED: Vite + React + TypeScript; entry src/main.tsx (createRoot);
  app shell src/App.tsx (BrowserRouter, Routes, providers).

2) Backend API (REST)
- Role: auth, validation, persistence, file I/O, JSON/binary responses.
- HOW CREATED (Express path): Backend/server.js — express(), cors middleware,
  express.json(), route mounts, mongoose connect, listen(PORT).
- HOW CREATED (FastAPI path): Backend/main.py — FastAPI app, CORSMiddleware,
  include_router for scan/items; uvicorn entry; optional second stack.

3) Data / storage
- Role: user records, scan metadata, binary DICOM on disk.
- HOW CREATED: MongoDB via mongoose (Node) or motor/pymongo (Python); multer
  diskStorage (Node) or UploadFile write to Path (FastAPI); local folder
  uploads/dicom.


Communication:
- HTTP request/response; JSON for most APIs; raw file bytes for GET .../file.
- HOW CREATED: browser fetch (frontend); res.json / res.sendFile (Express);
  FileResponse / JSONResponse (FastAPI).


--------------------------------------------------------------------------------
2) STARTUP PIPELINE
--------------------------------------------------------------------------------

Frontend startup:
1) Load bundle from Vite dev server or static host.
2) main.tsx mounts <App /> in StrictMode.
3) Providers run (Theme, Toast, Confirm, Auth).
4) AuthContext: read localStorage token; fetch GET /api/auth/me with Bearer.
5) Router matches URL; renders page + layout.

HOW CREATED: Vite (import.meta.env); react-dom createRoot; react-router-dom;
React Context providers in src/contexts/*.tsx.

Backend startup (Express):
1) dotenv loads Backend/.env (path joined in server.js).
2) express() app; cors({ origin: [...] }); express.json().
3) Routes: /api/health, /api/items, /api/scan, /api/auth.
4) await connectDB() (mongoose).
5) app.listen(PORT).

HOW CREATED: ES modules (package.json "type": "module"); Backend/server.js;
Backend/config/db.js for mongoose.connect.

Backend startup (FastAPI):
1) pydantic-settings loads env in config.py.
2) FastAPI app + lifespan; CORSMiddleware.
3) get_client() AsyncIOMotorClient; routers mounted.
4) uvicorn main:app --reload (optional).

HOW CREATED: Backend/main.py, Backend/database.py, Backend/routers/*.py.


--------------------------------------------------------------------------------
3) AUTH PIPELINE (REGISTER -> LOGIN -> SESSION -> PROTECTED UI)
--------------------------------------------------------------------------------

Register:
- Frontend: Signup form -> POST /api/auth/register (JSON body).
  HOW CREATED: AuthContext register(); fetch + JSON.stringify; React controlled
  inputs.
- Express: validate body; normalize email; User.create; jwt.sign; 201 JSON.
  HOW CREATED: Backend/routes/auth.routes.js; User model pre-save bcrypt hash
  (bcryptjs in User.js); jsonwebtoken.

Login:
- Frontend: POST /api/auth/login.
  HOW CREATED: AuthContext login(); same fetch pattern.
- Express: find user; user.comparePassword; jwt.sign; 200 JSON.
  HOW CREATED: auth.routes.js; bcrypt.compare via model method.

Session restore (/me):
- Frontend: GET /api/auth/me with Authorization: Bearer.
  HOW CREATED: AuthContext loadUser(); authHeaders from src/lib/apiAuth.ts.
- Express: authMiddleware verifies JWT; attaches req.user; returns user JSON.
  HOW CREATED: Backend/middleware/auth.js — jwt.verify, User.findById.

Protected /app UI:
- Frontend: ProtectedLayout uses useAuth; Navigate to /login if no user.
  HOW CREATED: ProtectedLayout.tsx + react-router-dom Navigate, Outlet.

Doctor note: UI protection complements but does not replace server auth on APIs.


--------------------------------------------------------------------------------
4) DICOM UPLOAD PIPELINE (END-TO-END)
--------------------------------------------------------------------------------

A) Client file selection:
- HOW CREATED: React state + <input type="file"> and/or drag-drop in
  UploadScan.tsx (and Compare where used); optional dicom-parser read for tags.

B) Multipart request:
- HOW CREATED: FormData.append('file', file); fetch POST /api/scan/upload;
  browser sets multipart boundary; Authorization from authHeaders().

C) Express handling:
- HOW CREATED: scan.routes.js — router.use(authMiddleware); multer upload.single('file');
  fileFilter for .dcm/.dicom or application/dicom; limits.fileSize 500MB;
  diskStorage writes under Backend/uploads/dicom.

D) Duplicate handling:
- HOW CREATED: Scan.findOne by userId + originalName + studyDate (+ patient match);
  if duplicate -> 201 JSON with skipped: true.

E) DB insert:
- HOW CREATED: Scan.create({ userId, doctorName from req.user.name, path from
  multer, size, mimeType, patientName, studyDate, modality }); mongoose model
  Backend/models/Scan.js.

F) Response + UI:
- HOW CREATED: res.status(201).json(...); frontend parses JSON; ToastContext or
  inline message.


--------------------------------------------------------------------------------
5) SCAN LIST / METADATA / FILE / DELETE
--------------------------------------------------------------------------------

List GET /api/scan:
- HOW CREATED (Express): authMiddleware; Scan.find({ userId: req.user._id })
  .sort({ createdAt: -1 }).select(...).lean(); map _id to id in JSON.

Detail GET /api/scan/:id:
- HOW CREATED: Scan.findOne({ _id, userId }); 404 if missing.

File GET /api/scan/:id/file:
- HOW CREATED: resolve path; path.resolve(scan.path).startsWith(UPLOAD_DIR);
  res.setHeader Content-Type; res.sendFile(absolutePath).

Delete DELETE /api/scan/:id:
- HOW CREATED: findOne; fs.unlinkSync if inside UPLOAD_DIR; Scan.deleteOne.

Frontend consumption:
- HOW CREATED: fetch with authHeaders; res.json() for lists; res.arrayBuffer()
  for DICOM bytes in Analysis Studio / viewer flow.

6) DATA FLOW MODEL (WHAT MOVES WHERE + HOW CREATED)
--------------------------------------------------------------------------------

Identity:
- Token in localStorage (coronet-token); user in React state; password hash in
  MongoDB users collection.
- HOW CREATED: localStorage API; AuthContext; mongoose User schema with bcrypt
  pre-save.

Scan metadata:
- Form fields + server fields -> MongoDB scans documents.
- HOW CREATED: mongoose schema fields; JSON over HTTP.

File bytes:
- Browser -> multer -> disk path string in DB -> sendFile back to client.
- HOW CREATED: multer + fs; Express static file response.

Feedback:
- HTTP status + { error: "..." } or success payloads; toasts in UI.
- HOW CREATED: Express error middleware; ToastContext on client.


--------------------------------------------------------------------------------
7) SECURITY PIPELINE (+ HOW CREATED)
--------------------------------------------------------------------------------

Implemented (Express stack):
- Password hashing: bcryptjs in User model pre-save hook.
- JWT: jsonwebtoken sign/verify; secret from process.env.JWT_SECRET.
- Protected scan routes: authMiddleware on router in scan.routes.js.
- User-scoped queries: userId on Scan documents.
- CORS: cors package with allow-list built from env + localhost:5173.
- Upload validation: multer fileFilter + size limit.
- Path traversal guard: resolved path must stay under UPLOAD_DIR before sendFile.

HOW CREATED: packages above; implementation in middleware/auth.js,
routes/scan.routes.js, server.js CORS array.

Honest gaps (discussion):
- JWT in localStorage (XSS risk); no rate limit in repo; no Helmet layer;
  role-based RBAC not fully modeled in frontend.

Future hardening HOW (conceptual): httpOnly cookies + CSRF; express-rate-limit;
helmet; refresh tokens; audit logs.

FastAPI:
- HTTPException; custom handler in main.py flattening detail to { error }.
- HOW CREATED: FastAPI exception_handler registration.

13) HARD QUESTIONS — SHORT ANSWERS (+ WHERE IN STACK)
--------------------------------------------------------------------------------

Q: Where is authorization enforced?
A: Express scan router uses authMiddleware + userId filter — server-side.

Q: Why validate on both client and server?
A: Client = UX; server = trust boundary (multer + mongoose + auth).

Q: How are files secured on disk?
A: Randomized safe names; path stored in DB; send only after path.resolve check
  inside upload directory.

Q: Single source of truth for API URL?
A: Frontend VITE_API_URL; backend own host/port — documented in .env.example.


--------------------------------------------------------------------------------
14) ONE-MINUTE FULL PIPELINE SUMMARY
--------------------------------------------------------------------------------

The COROnet pipeline is a Vite-built React SPA that talks over HTTP to an Express
REST API backed by MongoDB and local DICOM storage. The frontend uses React
Router, Context, and fetch; the backend uses Express middleware, mongoose models,
JWT auth, and multer uploads. Responses are JSON except for binary DICOM
delivery. Optional FastAPI code offers a Python parallel for future AI-heavy
services. The design separates presentation, application API, and persistence
with clear security and validation responsibilities at the server.
